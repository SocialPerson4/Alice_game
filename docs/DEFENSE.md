# 答辩问题与参考回答

以下回答应结合你实际掌握的源码复述，不要逐字背诵。

## 项目与个人职责

### 1. 这是个人项目还是团队项目？你具体做了什么？

这是五人课程团队项目。我主要完成第五章的前端交互、音频和剧本设计；后端及数据库由我和王智龙协作完成。我重点参与了 Express 业务接口、MySQL 表结构和前后端联调，其余章节及美术按 README 中的分工完成。

### 2. 为什么简历上不写 Java？

因为当前可公开复现的代码使用 Node.js/Express，仓库中没有 Java 后端。简历应与代码一致，否则无法经受追问。Node.js 对此前端占比较高的课程项目也更便于统一语言和快速联调。

## 前端与交互原理

### 3. 第五章的分支剧情如何实现？

核心是有限状态推进：保存当前场景、对话索引、玩家选择和角色状态；用户点击后根据状态切换文本、立绘和背景。遇到选择节点时暂停线性推进，由选项处理函数修改状态，再进入对应分支。结局由关键选择和状态组合判定。

### 4. 为什么要把场景推进和 DOM 更新分开？

状态负责描述“现在发生了什么”，渲染函数负责把状态映射到页面。这样更容易定位分支错误，也便于后来增加存档、回放或自动测试；如果把剧情判断全部写在点击事件里，分支增长后会很难维护。

### 5. Web Audio API 与直接使用 audio 标签有什么区别？

`audio` 标签适合简单播放；Web Audio API 可以建立音频节点图，控制增益、混音、渐变和触发时机。项目中两者结合：长背景音乐使用音频资源，交互反馈通过统一的音频管理逻辑控制音量和静音状态。

### 6. 多结局如何避免条件冲突？

先定义互斥且有优先级的结局条件，再集中在一个判定入口处理，而不是分散到多个按钮事件中。调试时分别构造边界状态，确认每组状态只会命中预期结局。

## 后端与数据库原理

### 7. 登录链路是怎样的？

注册时校验参数并用 bcrypt 对密码做带盐哈希；登录时查询用户并比较哈希，通过后签发包含用户标识的 JWT。客户端后续在 `Authorization: Bearer <token>` 中携带令牌，鉴权中间件验证后再访问成就、音频和道具接口。

### 8. 为什么不能明文保存密码？

数据库一旦泄露，明文密码会直接暴露并可能影响用户在其他网站的账号。bcrypt 是针对密码设计的慢哈希算法，工作因子可以提高暴力破解成本。哈希不可替代 TLS，正式部署仍要使用 HTTPS。

### 9. JWT 的优点和局限是什么？

优点是服务端不必为每次请求查询会话，接口扩展较简单；局限是签发后难以立即撤销，一旦泄露会在过期前被滥用。生产系统应使用较短有效期、刷新令牌、密钥轮换或黑名单，并通过 HTTPS 和安全存储降低泄露风险。

### 10. 为什么使用连接池？

频繁新建数据库连接开销较大。连接池复用已有连接并限制并发连接数量，可以降低握手成本并避免请求高峰耗尽数据库资源。项目通过环境变量控制池大小。

### 11. 如何避免 SQL 注入？

接口使用 `?` 占位符和参数数组，把 SQL 结构与用户数据分开交给驱动处理，不通过字符串拼接生成查询。同时对用户名、密码长度和业务字段做输入校验。

### 12. 外键和联合唯一索引解决了什么问题？

外键保证用户删除时相关设置、成就和背包记录能级联处理；`(user_id, name)` 和 `(user_id, item_id)` 的联合唯一约束避免同一用户出现重复成就或重复道具状态。

## 工程与反思

### 13. 这次仓库重构做了什么？

将服务端、静态页面、数据库和文档分别放入 `src`、`public`、`database` 和 `docs`；删除 `node_modules`、IDE 配置和数据库导出；将固定密码与 JWT 密钥改为环境变量；合并冲突 SQL，并增加结构检查、健康接口和基础测试。

### 14. 项目目前最大的不足是什么？

自动测试只覆盖健康接口和静态首页，核心业务仍依赖真实 MySQL；前端章节代码的复用不足，媒体资源较大；JWT 缺少刷新和撤销机制。下一步会抽离统一剧情引擎，增加容器化数据库和接口集成测试，并压缩媒体资源。

### 15. Cursor 或其他 AI 工具具体起了什么作用？

主要用于查资料、代码补全、语法排查和剧情发散。生成内容不会直接合入：先检查 API 和数据结构，再在本地运行并针对实际页面调整。AI 提高了检索和样板代码效率，但模块拆分、联调和最终验证仍由成员完成。
